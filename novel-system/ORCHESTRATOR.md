## 一、系统概述

本系统是一个 **自包含的小说写作循环系统**，用于从零到完稿的全流程自动化创作。系统围绕 **8级门禁控制（G0-G7 + G8人类终审）** 构建，确保每一章在写作、质检、落盘各环节均通过量化检查后才进入下一章。

### 1.1 设计目标

| 目标 | 说明 |
|---|---|
| 质量达标 | σ²≥120, TTR≥0.48, EGR≤2.0, Pσ²≥300，消除AI检测风险 |
| 节奏合规 | 3章一小爽、10章一大爆、3:1张弛比，憋屈不超2章 |
| 平台适配 | 番茄小说女频爽文赛道，单章1200-1500字 |
| 风格稳定 | 跨章SC≥0.75，人物声音不漂移 |
| 状态持久 | 15个动态轨文件全程记录，会话断开可恢复 |

### 1.2 项目背景说明

本模板不预置任何具体项目背景。启动新书时，项目背景由阶段0（新书模式执行协议）的各步骤动态生成：

| 生成步骤 | 产出 | 落盘位置 |
|---|---|---|
| 步骤1 选题市场调研 | 市场调研报告 | `static/market_research.md` |
| 步骤2 选题确认 | 选题确认书 | `dynamic/00_INDEX.md` |
| 步骤2.5 核心创意卡录入 | 核心创意卡（AI不可改写） | `dynamic/00_INDEX.md` |
| 步骤3-6 | 三幕大纲 / 人物档案 / 节奏规划 / 运营包装 | `static/` 各静态轨文件 |

> 若为已有项目的续写或重写，启动时由用户提供项目背景与已知风险（如爽点不足、节奏慢、AI检测风险、缺情感线等常见问题），作为选题与大纲阶段的规避约束，写入 `dynamic/00_INDEX.md`。

### 1.3 门禁总览

```
G0  选题+大纲终稿人类审核（新书模式专属）
 │
 ├── G1  状态加载门 — 读取15个动态轨文件
 │   ├── G2  模仿学习门 — 提取样本特征卡
 │   │   ├── G3  写作门 — 草稿生成 + 禁词扫描
 │   │   │   ├── G4  平台规则门 — 字数/节奏/合规
 │   │   │   ├── G5  metrics指标门 — σ²/TTR/EGR/Pσ²
 │   │   │   ├── G6  动态轨一致性门 — 人物/伏笔/时间线
 │   │   │   └── G7  状态落盘门 — 12项WRITE-CHECK
 │   │   └── (循环下一章)
 │   └──
 └── G8  人类终审 — 用户阅读确认（可选，默认跳过）
```

> **铁律**：任何门禁未通过，不得进入下一阶段。门禁失败时触发修复循环，最多重试3次，仍不通过则暂停并请求人类介入。

## 二、新书模式执行协议（阶段0：全局规划）

> **触发条件**：用户说"启动新书""开始新项目""从零开始写"时执行。
> **目标**：完成选题→大纲→人物→节奏→运营包装的全局规划，产出故事圣经（Story Bible）。
> **输出路径**：`static/` 目录（市场报告、选题卡、大纲、人物、节奏、包装等静态轨）

### 步骤1：选题市场调研

**目的**：基于2026年市场数据，确认番茄热门题材方向与目标题材赛道对标作品。

**执行操作**：

1. 用 WebSearch 并行搜索三组关键词（以2026为时间锚点）：
   - `2026 番茄小说热门题材 女频爽文 重生系统流`
   - `2026 [题材]小说 网文 对标作品 爽文打脸`
   - `2026 网文赚钱题材 番茄小说 收入排行 女频`

2. 用 WebFetch 抓取信息密度最高的2-3个页面，提取：
   - 番茄标签热度数值（万）
   - 短剧改编率（%）
   - 搜索量同比增速（%）
   - 完读率/首章留存率（%）
   - 新人门槛评级
   - 目标题材已有作品及其表现

3. 生成横向对比表，列字段：题材赛道 | 热度 | 增速 | 短剧改编率 | 新人门槛 | 综合赚钱指数

4. 输出 TOP 3 推荐选题，每个附：爆款公式 + 代表作 + 平台适配 + 避坑提示

**输出文件**：`static/market_research.md`

**红线**：
- 必须标注数据来源与时间，网文市场变化快，过期数据会误导
- 热度≠赚钱，必须叠加"改编率+门槛+增速"三维度
- 2026年已降温赛道：纯玄幻仙侠、无脑签到、纯甜宠、老套霸总、狗血宅斗
- 目标题材需确认是否已被过度开发，寻找差异化切入点

3. 向用户展示选题方案，等待确认

**输出**：选题确认书（写入 `dynamic/00_INDEX.md` 的项目信息区）

**选题方案示例**（实际内容以核心创意卡和市场报告为准）：

| 题材标签 | [如 重生 / 系统 / [题材] / 打脸 / 逆袭] |

### 步骤2.5：核心创意卡录入

**目的**：把作者的核心创意固化为设定基底，后续所有模块以此为约束。

**执行操作**：

1. 向用户展示核心创意卡模板，引导填写5项核心设定
2. 用户确认后，将创意卡写入 `dynamic/00_INDEX.md` 的"作者核心创意卡"区域
3. 标记为 **AI不可改写** 约束

**创意卡模板**：

```
═══ 作者核心创意卡 ═══
城市:      [一句话，如"北京"]
行业:      [一句话，如"餐饮"]
核心能力:  [一句话，如"重生记忆+行业知识系统"]
核心矛盾:  [一句话，如"前世被背刺致死，重生后打翻整个行业圈"]
创意差异化: [一句话，即"我的故事独特在哪"]
════════════════════════
```

**创意卡填写示例**：

| 设定项 | 内容 |
|---|---|
| 城市 | [如 北京] |
| 行业 | [如 餐饮] |
| 核心能力/金手指 | [如 重生记忆 + 行业知识系统（可看穿对方真实意图+供应链溯源）] |
| 核心矛盾 | [如 前世被信任之人背刺至身败名裂，重生后用前世记忆和核心能力主动碾压] |

> **约束规则**：
> 1. 作者填写部分总计不超过200字，避免过度设定。细节由后续模块补齐
> 2. 此卡写入故事圣经后，后续所有模块以此为约束，不可偏离
> 3. AI不可改写这5项核心设定

### 步骤2.8：素材准备

**目的**：为写作阶段预载行业素材、打脸场景素材、情感线素材，确保专业细节可信。

**执行操作**（行业素材按核心创意卡指定的行业产出）：

1. **行业素材库**（写入 `dynamic/material-prep-report.md`）：
   - 行业业务分类与资质/分级体系（监管边界、超范围经营的典型手法）
   - 常见套路话术（低价引流→层层升单→制造焦虑）
   - 供应链灰色地带案例（非正规渠道产品、造假手法、以次充好）
   - 监管法规要点（主管部门认证、执业合规、消费者权益）
   - 行业数据（市场规模、从业主体数量、投诉量）

2. **打脸场景素材库**（写入 `dynamic/material-prep-report.md`）：
   - 专业碾压话术（用专业依据拆解销售话术）
   - 公开场合打脸模板（行业交流会、法庭、媒体采访）
   - 反派被打脸后的反应谱（从不信→震惊→恼怒→崩溃→反扑）
   - 爽点节奏模板（蓄力→爆发→余韵三段式）

3. **情感线素材库**（写入 `dynamic/material-prep-report.md`）：
   - 重生文经典情感节奏（前世遗憾→今生试探→信任重建→并肩作战）
   - 行业背景下的暧昧场景设计（深夜送资料、并肩查证据、关键节点外的等待）
   - 男主设定方向（按行业特点选择：资源信息型 / 专业技能型 / 资本型）
   - 情感升温节点与主线爆点的交织方式

**红线**：
- 素材库不是大纲，是写作时可调取的"弹药库"
- 每条素材标注来源，虚构素材标注"创作设定"
- 行业素材需确保法规准确性，错误的法律/专业信息会导致平台下架

### 步骤3：三幕结构大纲

**目的**：产出200-330章的完整三幕结构大纲（首本限制30-50万字）。

**执行操作**：

1. **确定篇幅档位**：首本限制为"中篇"（30-50万字 / 200-330章 / 单章1200-1500字）
2. **划分三幕比例**：22% : 30% : 30% : 18%（一幕:二上:二下:三幕）
3. **逐卷规划**：
   - 每卷10章，标注卷名、情感目标、核心任务
   - 每章一行：章号 | 内容摘要 | 情绪落点 | 章末钩子
   - 标注爽点章（每3章1小爽）和大爆点章（每10章1大爆）
4. **植入伏笔注册表**：标注每个伏笔的种植章号和计划回收章号
5. **绘制副线编织图**：主线、情感线、成长线、悬疑线、反线、群像线的交汇点

**结构框架（示例）**：

```
幕          卷          章数        情感目标    核心任务
─────────────────────────────────────────────────────────
第一幕      第1卷       1-30        爽+燃      重生归来·初次碾压
重生碾压    第2卷       31-60       燃+紧张    系统升级·正面交锋
─────────────────────────────────────────────────────────
第二幕上    第3卷       61-90       爽+燃      降维打击·行业震动
绝地反击    第4卷       91-120      紧张+燃    资本反扑·法律对决
            第5卷上     121-140     燃+感动    证据收网·信任深化
─────────────────────────────────────────────────────────
第二幕下    第5卷下     141-150     燃+释然    反派反水·真相浮现
巅峰对决    第6卷       151-180     释然+感动  至暗时刻→真相揭露
            第7卷       181-210     感动+满足  监管出手·反派崩塌
            第8卷上     211-220     满足       收网
─────────────────────────────────────────────────────────
第三幕      第8卷下     221-240     满足+回味  新标准·情感收束
新生        第9卷       241-270     回味       回到原点·番外
```

**节奏铁律**：
- 3章一小爽：每3章必须有打脸/反转/小进展
- 10章一大爆：每10章一个重大爆点（见爆点清单）
- 憋屈不超2章：主角受委屈最多2章，第3章必须反击
- 每章末留钩子：章末必须有悬念驱动翻页
- 3:1张弛比：每3章紧张后必须有1章释放/日常/情感

**输出文件**：`static/outline.md`

### 步骤4：人物档案

**目的**：产出完整人物档案，确保角色有灵魂、有区分度、有成长弧光。

**执行操作**：

为每个主要角色填写以下维度：

1. **基础设定**：姓名/年龄/外表标签/身份
2. **核心能力**：逆袭资本或威胁来源
3. **致命缺陷**：导致困境或 downfall 的性格弱点
4. **前史创伤**：塑造行为动机的过去事件
5. **人物弧光**：从A状态到B状态的成长/堕落轨迹
6. **语言指纹**：句长偏好、用词偏好、说话节奏、口头禅
7. **反差点**：外表vs内在、公开vs私下的反差

#### Soul Field 铁律

> **定义**：Soul Field（灵魂场）是角色的不可违背的核心特质集合，用于防止人物漂移。

**每个角色必须定义以下Soul Field元素**：

| 元素 | 说明 | 示例（主角） |
|---|---|---|
| 核心信念 | 角色最深层的价值观，不会因剧情改变 | "良知不是软肋，是底线" |
| 行为边界 | 角色绝对不会做的事 | 绝不会为了利益牺牲无辜者的健康与权益 |
| 情感锚点 | 角色所有情绪的根源 | 至亲的遭遇——一切行为的起点 |
| 语言DNA | 角色说话的不可替代特征 | 短句利落+方言口头禅+固定比喻习惯 |
| 反应模式 | 面对压力时的固定行为模式 | 紧张时沉默不说话，反击时语速变快句子变短 |

**Soul Field 检查规则**：
- 每章写作前加载角色Soul Field，确保本章行为不违背
- 如剧情需要角色"违背"Soul Field，必须铺垫充分的转变动机
- G6门禁检查：本章角色行为是否与Soul Field一致
- 违背Soul Field且无铺垫 → G6失败，触发重写

**输出文件**：`static/characters.md`

### 步骤5：节奏规划

**目的**：将大纲转化为可执行的节奏检查表，确保每3章有爽点、每10章有爆点。

**执行操作**：

1. **生成10章一爆点清单**：列出全书所有大爆点的章号、事件、情感强度
2. **生成3章一爽点清单**：标注每3章区间的小爽点类型
3. **生成张弛比检查表**：标注每章的紧张/释放状态，确保3:1比例
4. **标注情感线节点**：情感升温的关键章节和方式
5. **标注伏笔回收时间线**：确保伏笔不超过20章未回收（标黄）、不超过40章（标红强制处理）

**爽点类型库**：

| 类型 | 说明 | 示例 |
|---|---|---|
| 专业碾压 | 用知识实力当面打脸 | 三句话拆解销售话术，对方哑口无言 |
| 信息差打脸 | 用前世记忆提前布局 | 反派设的局被主角早已识破并反将一军 |
| 系统加持 | 金手指能力展示 | 系统激活核心能力，一眼看穿对手的伪装与套路 |
| 法律反转 | 法庭上的逆转 | 关键证据当庭提交，对方措手不及 |
| 口碑碾压 | 群众认可的力量 | 受助者自发传播，反派的谣言被真相淹没 |
| 反派自爆 | 反派搬起石头砸自己脚 | 设的局反噬自身，当众出丑 |

**输出文件**：节奏规划写入 `static/outline.md` 的节奏检查表区域

### 步骤6：运营包装

**目的**：产出符合番茄平台调性的书名、简介、标签。

**执行操作**：

1. **书名**（三选一推荐）：
   - 必须直给、类型化，前6个字让读者知道是什么题材
   - 包含核心卖点关键词（如 重生/[题材]/打脸/逆袭）
   - 避免文艺化书名（商业平台需要直给的书名）

2. **短简介**（100字内，用于推荐位展示）：
   - 必须包含：主角困境 + 金手指 + 爽点预告
   - 句式短促有力，像广告语而非大纲

3. **长简介**（200-300字，用于书籍详情页）：
   - 必须包含：前史钩子 + 重生转折 + 核心冲突 + 情感线暗示
   - 末尾留悬念，驱动点击阅读

4. **标签**：
   - 主标签：3个（如 #重生 #[题材] #打脸爽文）
   - 副标签：4-5个（如 #系统流 #女性逆袭 #行业揭露 #都市）

**输出文件**：`static/packaging.md`

### 步骤7：创意扰动审查

**目的**：在大纲和人物定稿前，进行一次全局创意审查，防止同质化。

**执行操作**：

1. **同质化自检**：
   - 与市面已有[题材]/重生/打脸小说对比，找出雷同点
   - 检查开头方式是否与同类作品趋同
   - 检查金手指设定是否与其他系统流小说撞车

2. **创意扰动注入**：
   - 如果检测到同质化风险，注入1-2个反预期元素
   - 扰动选项示例：
     - "视角偏移"：用配角视角开场再切回主角
     - "物件叙事"：用一个物件串起全章
     - "反预期反应"：角色做出意料之外但合理的反应
   - 扰动是"给选项不替决定"，作者可选一个或全部拒绝

3. **差异化确认**：
   - 明确本作品与同类作品的3个核心差异点
   - 差异点写入创意卡，作为写作约束

**输出文件**：审查结果写入 `dynamic/decisions.md`

### G2：模仿学习门

**目的**：从同类爆款中提取写作特征卡，为本章写作提供风格参照。

**执行操作**：

1. **样本刷新**（每10章刷新一次样本库）：

   - 搜索关键词模板：`[题材类型] 爆款片段 [章节类型] 示例`
   - 抓取2-3个高热度片段作为新样本

   - 将样本特征卡存入 `dynamic/sample_library.json`

2. **样本特征卡提取**：
   - 入场方式（dialogue/scene/action/sensory/psychological/narrative）
   - 章末钩子类型（悬念/反转/预告/情感/信息差）
   - 对话占比参考值
   - σ²/TTR/EGR/Pσ² 参考值
   - 节奏特征（快节奏/中速/慢热）

3. **本章匹配**：
   - 根据本章在大纲中的类型（爽点章/过渡章/情感章/爆点章），匹配最合适的样本
   - 提取本章写作目标特征卡

**G2通过条件**：
- `sample_library.json` 中至少有1个与本章类型匹配的样本
- 样本特征卡提取完成（入场方式+钩子类型+4项metrics参考值）

**G2失败处理**：
- 样本库为空 → 用默认特征卡（σ²≥150, TTR≥0.55, EGR≤1.5, Pσ²≥400）
- 样本不匹配 → 使用最近一次刷新的通用样本

### G3：写作门

**目的**：生成本章草稿并进行禁词扫描。

**执行操作**：

1. **写作前准备**：
   - 加载本章大纲条目（内容摘要+情绪落点+章末钩子）

2. **草稿生成**：
   - 单章字数目标：1200-1500字（中文字符，不含标点）
   - 前3章特殊要求见"四、前3章特殊流程"
   - 写作时遵循以下约束：
     - 长短句交替（σ²≥120，目标≥150）

     - 感官词优先于笼统情感词（EGR≤2.0，目标≤1.5）
     - 用词多样（TTR≥0.48，目标≥0.55）
     - 植入语言指纹≥2次/章
     - 章末必须留钩子
     - 对话与叙述比例适当（对话占比15%-40%）

3. **禁词扫描**：
   - 扫描政治敏感词、色情敏感词、暴力敏感词

   - 扫描结果写入 `dynamic/compliance-log.md`

**G3通过条件**：
- 草稿字数在1200-1500字之间（中文字符，不含标点）
- 禁词扫描无命中
- 章末有钩子

**G3失败处理**：
- 字数不足 → 补充细节和对话
- 字数超标 → 精简描写，拆分为两章
- 禁词命中 → 替换为安全表述

### G5：metrics指标门

**目的**：用量化指标确保文风达到人写标准，消除AI检测风险。

**执行操作**：

1. 用 `tools/metrics.py` 计算本章草稿的4项B组指标：

| 指标 | 含义 | 门限 | 人写区间 | AI区间 |
|---|---|---|---|---|
| σ² | 句长方差（标准差） | ≥120 | >150 | <80 |
| TTR | 用词多样性（独特词/总词） | ≥0.48 | >0.55 | <0.42 |
| EGR | 情感颗粒度比（笼统词/感官词） | ≤2.0 | <1.5 | >3.0 |
| Pσ² | 段落长度方差（标准差） | ≥300 | >400 | <200 |

2. 计算C组卷级指标（每10章检查一次）：

| 指标 | 含义 | 门限 |
|---|---|---|
| Cσ² | 连接词密度方差 | ≥1.0 |
| Iσ² | 信息密度方差 | ≥1.8 |
| FP | 语言指纹匹配次数 | ≥2次/章 |
| SC | 文风稳定性系数（跨章） | ≥0.75 |

3. 检查指标是否达标，生成纠正建议

**G5通过条件**：
- B组4项指标全部达标（σ²≥120, TTR≥0.48, EGR≤2.0, Pσ²≥300）
- 如有指纹库，FP≥2

**G5失败处理**：
- σ²<120 → 插入短句（3-5字）打断节奏，或将长句拆为两句
- TTR<0.48 → 替换高频词的30%为同义词，加入个人习惯用语
- EGR>2.0 → 将笼统情感词替换为具体感官描写（胃紧/手凉/视野发白）
- Pσ²<300 → 合并或拆分段落，制造长短段交替
- FP<2 → 植入口头禅/标志性动作
- 修复后重新计算指标，最多重试3次

**命令示例**：
```bash
python tools/metrics.py chapters/ch001.md
python tools/metrics.py chapters/ch001.md --json
python tools/metrics.py chapters/ch001.md --fingerprint dynamic/fingerprint.json
```

## 四、前3章特殊流程

> **原则**：前3章决定留存率，是全书的"生死线"。番茄编辑审稿时间约几分钟，前300字决定生死。

### 4.1 前3章质量要求

| 维度 | 标准 | 反面示例 |
|---|---|---|
| 前300字 | 直接冲突切入，无铺垫描写 | 用环境/体感描写开场铺垫 |
| 第一章 | 重生触发 + 初次打脸/反转 | 只有日常交代，无冲突事件 |
| 第二章 | 打脸升级 + 情感线种子 | 冲突原地打转，不升级 |
| 第三章 | 第一个小爽点释放 | 主角仍被动挨打，无爽点 |
| σ² | ≥150（人写区间） | 句式单一（AI区间） |
| 字数 | 1200-1500字 | 严重超标（如1800-2200字） |

### 4.2 前3章特殊流程

1. **双重G5检查**：前3章的metrics指标需达到人写区间（σ²>150, TTR>0.55, EGR<1.5, Pσ²>400），而非仅达标
2. **开篇钩子审查**：前300字必须包含至少1个冲突元素（背叛/危机/反转/悬念）
3. **读者代入测试**：模拟读者视角，检查"前3章是否让人想继续读"
4. **额外打磨轮次**：前3章允许最多5次重写（普通章最多3次）
5. **用户强制审核**：前3章完成后必须经过G8用户审核，不可跳过

### 4.3 前3章内容规划（示例）

| 章 | 内容 | 情绪落点 | 章末钩子 |
|---|---|---|---|
| 1 | 主角重生回到关键节点——成果被对手署名抢夺的瞬间。前世隐忍，这一世当场起身反击。金手指激活：识破对手的数据造假 | 先抑后扬→重生爽感 | 对手脸色一变："你怎么知道这些数据是假的？" |
| 2 | 主角用前世记忆提前布局：抢先发布真相+联系关键证人+锁定核心线索。对手反手甩锅，被主角用证据堵死 | 爽：主动出击碾压被动 | 关键人物注意到主角："这个人，变了" |
| 3 | 第一个小爽点：主角在内部会议上用专业能力当面拆解对手的"方案"——那是剽窃主角的成果，但对手根本不懂精髓 | 爽：专业碾压打脸 | 男二在旁观察，记下一行字："她不一样" |

## 五、质量标准

### 5.1 核心指标阈值

| 指标 | 门限值 | 人写区间 | AI区间 | 说明 |
|---|---|---|---|---|
| σ²（句长方差） | ≥120 | >150 | <80 | 衡量句式多样性 |
| TTR（用词多样性） | ≥0.48 | >0.55 | <0.42 | 衡量词汇丰富度 |
| EGR（情感颗粒度比） | ≤2.0 | <1.5 | >3.0 | 笼统情感词/感官词 |
| Pσ²（段落长度方差） | ≥300 | >400 | <200 | 衡量段落节奏 |
| Cσ²（连接词密度方差） | ≥1.0 | >1.5 | <0.5 | 卷级，过渡词分布 |
| Iσ²（信息密度方差） | ≥1.8 | >2.5 | <1.0 | 卷级，信息分布 |
| FP（语言指纹匹配） | ≥2次/章 | >3 | =0 | 个人习惯用语 |
| SC（文风稳定性系数） | ≥0.75 | >0.85 | <0.6 | 跨章指标稳定性 |

### 5.2 章节字数标准

| 维度 | 标准 |
|---|---|
| 单章字数 | 1200-1500字（中文字符，不含标点和空白） |
| 统计工具 | `tools/chapter-word-counter.py` |
| 超标处理 | 拆分为多章 |
| 不足处理 | 补充细节和对话 |

### 5.3 节奏标准

| 规则 | 标准 |
|---|---|
| 3章一小爽 | 每3章必须有打脸/反转/小进展 |
| 10章一大爆 | 每10章一个重大爆点 |
| 憋屈不超2章 | 主角受委屈最多连续2章 |
| 章末钩子 | 每章末尾必须留悬念 |
| 3:1张弛比 | 每3章紧张后必须有1章释放 |
| 伏笔回收预警 | 超20章未回收标黄，超40章标红强制处理 |

### 5.4 平台合规标准

| 规则 | 标准 |
|---|---|
| AI检测 | σ²/Pσ²必须在人写区间或达标区间 |
| 意识形态 | 不渲染系统性歧视/负面价值观 |
| 敏感内容 | 无政治/色情/暴力违禁词 |

## 六、故障恢复协议

### 6.1 会话断开恢复

**场景**：写作过程中会话意外断开（如超时、网络中断、进程崩溃）。

**恢复流程**：

1. 读取 `dynamic/gate-log.md`，确认断开时最后通过的门禁：
   - G3写作中断 → 读取 `chapters/chXXX_draft.md` 草稿，从断点继续
   - G4/G5/G6质检中断 → 重新执行当前门禁
   - G7落盘中断 → 检查已落盘的文件，补全未完成的WRITE-CHECK
   - 上一章G7已通过 → 正常开始下一章

2. 读取 `dynamic/progress.md` 确认当前章号

3. 读取15个动态轨恢复全部状态

4. 从断开点继续执行，不重复已完成的步骤

**草稿文件**：
- G3写作的草稿即 `chapters/chXXX_draft.md`，终稿为 `chXXX_final.md`
- G7落盘成功后删除临时文件
- 恢复时如发现临时文件存在，说明G3未完成

### 6.2 子Agent调用失败处理

**场景**：门禁检查中调用的工具（如metrics.py、chapter-word-counter.py）执行失败。

**处理策略**：

| 失败类型 | 处理方式 |
|---|---|
| 工具不存在 | 打印警告，使用内置简化逻辑替代，记录到 `gate-log.md` |
| 工具执行超时 | 重试1次，仍超时则跳过该项检查并标记为"待人工确认" |
| 工具输出异常 | 记录原始输出到 `dynamic/decisions.md`，请求人类确认 |
| 依赖缺失（如jieba） | 使用降级方案（按字符计算TTR），打印警告 |

**原则**：工具失败不阻塞创作流程，但必须在 `gate-log.md` 中标记，并在下次会话时优先修复。

### 6.3 门禁连续失败处理

**场景**：某一门禁连续3次未通过。

**处理策略**：

1. 记录失败原因到 `dynamic/gate-log.md`
2. 暂停当前章节的写作循环
3. 向用户报告失败原因和建议修改方向
4. 等待用户指示（重写/跳过/修改大纲/调整参数）
5. 用户确认后从G1重新开始当前章节

## 七、执行原则

### 7.1 核心原则

| 原则 | 说明 |
|---|---|
| **一次一章** | 每次循环只写一章，不批量生成。每章完成后等待用户指示或自动进入下一章 |
| **门禁必过** | 任何门禁未通过不得进入下一阶段。门禁失败触发修复循环，最多3次 |
| **用户只审G8** | G1-G7全自动执行，用户只需在G8（人类终审）时介入。前3章除外——前3章强制G8审核 |
| **状态落盘优先** | 任何操作完成后立即落盘。宁可多写一次文件，不可丢失状态 |

### 7.2 写作约束优先级

当约束冲突时，按以下优先级处理：

```
1. 平台合规（违禁词/意识形态）— 一票否决
2. Soul Field一致性 — 不可违背
3. 核心创意卡约束 — 不可偏离
4. 节奏铁律（3章爽/10章爆/憋屈≤2） — 必须满足
5. metrics指标门限 — 必须达标
6. 字数标准（1200-1500） — 必须满足
7. 伏笔回收时效 — 超期强制处理
8. 文风稳定性 — 尽量保持
```

### 7.3 自动化与人工分工

| 环节 | 自动/人工 | 说明 |
|---|---|---|
| 选题市场调研 | 自动执行，人工确认 | AI搜索+整理，用户确认方向 |
| 核心创意卡 | 人工填写 | 作者提供5项核心设定 |
| 大纲/人物/节奏 | 自动执行，人工确认 | AI生成，用户审核 |
| 章节写作（G1-G7） | 全自动 | 门禁自动执行 |
| 前3章审核 | 强制人工 | 前三章必须G8审核 |
| 后续章节审核 | 可选人工 | 默认跳过G8，用户可随时介入 |
| 故障恢复 | 自动恢复 | 读取状态文件，从断点继续 |

## 八、附录：工具命令速查

### 8.1 metrics.py（人写特征度量）

```bash
# 基础分析
python tools/metrics.py chapters/ch001.md

# JSON输出
python tools/metrics.py chapters/ch001.md --json

# 带语言指纹
python tools/metrics.py chapters/ch001.md --fingerprint dynamic/fingerprint.json

# 模仿评价（对比样本）
python tools/metrics.py chapters/ch001.md --compare samples/best_seller_ch1.txt

# 查重自检
python tools/metrics.py chapters/ch001.md --plagiarism samples/best_seller_ch1.txt

# 文风稳定性（跨章）
python tools/metrics.py ch048.md ch049.md ch050.md --stability

# 同质化检测+创意扰动
python tools/metrics.py ch048.md ch049.md ch050.md --perturb
```

### 8.2 chapter-word-counter.py（章节字数统计）

```bash
# 单章统计
python tools/chapter-word-counter.py chapters/ch001.md

# 批量统计
python tools/chapter-word-counter.py chapters/ch001.md chapters/ch002.md

# 通配符批量统计
python tools/chapter-word-counter.py "chapters/ch*.md"
```

### 8.3 feishu_sync.py（飞书文档同步）

```bash
# 初始化同步状态
python tools/feishu_sync.py --init

# 同步指定章节
python tools/feishu_sync.py --sync --chapter 1

# 指定触发类型
python tools/feishu_sync.py --sync --chapter 1 --trigger g7

# 强制全量同步
python tools/feishu_sync.py --sync --force
```
