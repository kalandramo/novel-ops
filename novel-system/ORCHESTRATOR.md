## 一、系统概述

本系统是一个 **自包含的小说写作循环系统**，用于从零到完稿的全流程自动化创作。系统围绕 **8级门禁控制（G0-G7 + G8人类终审）** 构建，确保每一章在写作、质检、落盘各环节均通过量化检查后才进入下一章。

### 1.1 设计目标

| 目标   | 说明                                                                                        |
| ---- | ----------------------------------------------------------------------------------------- |
| 质量达标 | σ²≥8, TTR≥0.40, Pσ²≥20, BurstCV≥0.40, ParaCV≥0.30, 3gramRep≤0.08, 3gramUniq≥0.85，消除AI检测风险 |
| 节奏合规 | 3章一小爽、10章一大爆、3:1张弛比，憋屈不超2章                                                                |
| 平台适配 | 番茄小说女频爽文赛道，单章1200-1500字                                                                   |
| 风格稳定 | 跨章SC≥0.75，人物声音不漂移                                                                         |
| 状态持久 | 18个动态轨文件全程记录，会话断开可恢复                                                                      |

### 1.2 项目背景说明

本模板不预置任何具体项目背景。启动新书时，项目背景由阶段0（新书模式执行协议）的各步骤动态生成：

| 生成步骤          | 产出                        | 落盘位置                        |
| ------------- | ------------------------- | --------------------------- |
| 步骤1 选题市场调研    | 市场调研报告                    | `static/market_research.md` |
| 步骤2 选题确认      | 选题确认书                     | `dynamic/00_INDEX.md`       |
| 步骤2.5 核心创意卡录入 | 核心创意卡（AI不可改写）             | `dynamic/00_INDEX.md`       |
| 步骤3-6         | 三幕大纲 / 人物档案 / 节奏规划 / 运营包装 | `static/` 各静态轨文件            |

> 若为已有项目的续写或重写，启动时由用户提供项目背景与已知风险（如爽点不足、节奏慢、AI检测风险、缺情感线等常见问题），作为选题与大纲阶段的规避约束，写入 `dynamic/00_INDEX.md`。

### 1.3 门禁总览

```
G0  选题+大纲终稿人类审核（新书模式专属）
 │   ├── G1  状态加载门 — 读取18个动态轨文件
 │   ├── G2  模仿学习门 — 提取样本特征卡
 │   │   ├── G3  写作门 — 草稿生成 + 禁词扫描
 │   │   │   ├── G4  平台规则门 — 字数/节奏/合规
 │   │   │   ├── G5  metrics指标门 — σ²/TTR/Pσ²/BurstCV/ParaCV/Ngram
 │   │   │   ├── G6  动态轨一致性门 — 人物/伏笔/时间线
 │   │   │   └── G7  状态落盘门 — 12项WRITE-CHECK
 │   │   └── (循环下一章)
 │   └──
 └── G8  人类终审 — 用户阅读确认（可选，默认跳过）
```

> **铁律**：任何门禁未通过，不得进入下一阶段。门禁失败时按质检模式处理（`QC_FULL`自动重写1次，仍不通过则暂停等用户决策 / `QC_CHECK`暂停等用户决定 / `QC_SKIP`该门禁已跳过）。

### 1.4 质检模式选择（写正式篇章前必选）

> **触发时机**：阶段0全局规划完成后、第一章正式写作前，系统必须询问用户选择质检模式。
> **核心考量**：质检门禁（G4/G5/G6）及自动重写会消耗大量token，用户需根据预算自主决定。

| 模式      | 代号         | 执行门禁                     | 失败处理                     | Token消耗 | 适用场景              |
| ------- | ---------- | ------------------------ | ------------------------ | ------- | ----------------- |
| 质检+自动重写 | `QC_FULL`  | G1→G7全部门禁                | 自动重写1次，仍不通过则暂停等用户决策      | 较高      | 追求质量、想控制token消耗   |
| 仅质检不重写  | `QC_CHECK` | G1→G7全部门禁                | 暂停并报告失败项，等待用户决定是否手动修改    | 中等      | 想了解质量但不想自动消耗token |
| 跳过质检    | `QC_SKIP`  | 仅G1+G3+G7（跳过G2/G4/G5/G6） | 直接输出，用户可事后手动运行metrics.py | 最低      | 预算有限、快速产出草稿       |

**执行操作**：

1. 向用户展示以上三种模式及token消耗说明
2. 等待用户选择（默认推荐`QC_FULL`）
3. 将用户选择写入 `dynamic/00_INDEX.md` 项目信息区的"质检模式"字段
4. 后续每章循环按所选模式执行门禁

**模式切换**：用户可在任意章节切换模式（如"从下章开始只质检不重写"），更新`00_INDEX.md`即可。

**门禁执行规则**：

| 门禁                      | QC\_FULL | QC\_CHECK | QC\_SKIP |
| ----------------------- | -------- | --------- | -------- |
| G1 状态加载                 | ✅ 执行     | ✅ 执行      | ✅ 执行     |
| G2 模仿学习                 | ✅ 执行     | ✅ 执行      | ⏭️ 跳过    |
| G3 写作（含R1-R5+Humanizer） | ✅ 执行     | ✅ 执行      | ✅ 执行     |
| G4 平台规则                 | ✅ 执行     | ✅ 执行      | ⏭️ 跳过    |
| G5 指标门禁                 | ✅ 执行     | ✅ 执行      | ⏭️ 跳过    |
| G6 一致性门禁                | ✅ 执行     | ✅ 执行      | ⏭️ 跳过    |
| G7 状态落盘                 | ✅ 执行     | ✅ 执行      | ✅ 执行     |

> `QC_SKIP`模式下，G3仍执行R1-R5铁律和Humanizer 3-Pass去AI化（内置在写作流程中，不额外消耗门禁token），但跳过G4/G5/G6的事后检查。用户可事后手动运行`python tools/metrics.py <章节文件>`自检质量。

## 二、独立流程：仿写模式

> **触发条件**：用户说"仿写""模仿写""学习这个风格写"时执行。
> **流程文件**：`prompts/imitate-prompt.md`
> **输入**：样本文件路径 + 仿写主题/大纲要求 + 目标字数（默认1200-1500）
> **特点**：独立于G1-G7门禁循环，不依赖18个动态轨文件，适用于无项目背景的单章仿写场景。

**执行操作**：读取 `prompts/imitate-prompt.md`，按6步流程执行：

1. **样本风格提取**：`metrics.py` 提取统计特征 + AI分析叙事结构 + 提取语言指纹
2. **风格规则生成**：将提取结果转化为可执行的写作约束（统计目标/结构模板/语言指纹）
3. **仿写生成**：加载 `writer-prompt.md` + 风格约束 + R1-R5铁律，生成草稿
4. **去AI化**：加载 `humanizer-prompt.md`，执行3-Pass管道
5. **仿写验证**：`metrics.py --compare` 风格相似度 + `--plagiarism` 抄袭检查 + `--aitext` AI检测
6. **输出**：仿写章节 + 风格相似度报告 + 改进建议

## 三、独立流程：续写模式

> **触发条件**：用户说"续写""接着写""继续往下写"时执行。
> **流程文件**：`prompts/continue-prompt.md`
> **输入**：已有章节目录路径 + 续写章数（默认1章）+ 是否走门禁（默认否）
> **特点**：默认不走G1-G7门禁循环，直接生成章节。用户明确要求"走门禁"时才执行G4/G5/G6检查。

**执行操作**：读取 `prompts/continue-prompt.md`，按5步流程执行：

1. **动态轨重建**：扫描已有章节，自动生成/更新18个动态轨文件（summaries/character-state/foreshadowing/next-hook/timeline/main-quest/location-index等）
2. **续写规划**：基于已有章节推断后续大纲和节奏
3. **生成下一章**：加载动态轨上下文 + writer-prompt + R1-R5铁律 + Humanizer去AI化
4. **可选门禁**：默认跳过。用户要求时执行G4(平台规则)/G5(metrics)/G6(一致性)
5. **输出**：续写章节 + 更新动态轨 + 下一章建议

> **与标准章节循环的区别**：标准循环走完整G1→G2→G3→G4→G5→G6→G7，续写流程默认跳过门禁，复用G3写作核心能力但不强制走循环。

## 四、新书模式执行协议（阶段0：全局规划）

> **触发条件**：用户说"启动新书""开始新项目""从零开始写"时执行。
> **目标**：完成选题→大纲→人物→节奏→运营包装的全局规划，产出故事圣经（Story Bible）。
> **输出路径**：`static/` 目录（市场报告、选题卡、大纲、人物、节奏、包装等静态轨）

### 步骤1：选题市场调研

**目的**：基于2026年市场数据，确认番茄热门题材方向与目标题材赛道对标作品。

**执行操作**：

1. **加载平台知识库**：读取 `knowledge/platform-patterns.md`，获取番茄/晋江/起点等9个平台的读者画像、节奏要求、章节标准、热门标签，作为后续调研的对标基准

2. 用 WebSearch 并行搜索三组关键词（以2026为时间锚点）：

   * `2026 番茄小说热门题材 女频爽文 重生系统流`

   * `2026 [题材]小说 网文 对标作品 爽文打脸`

   * `2026 网文赚钱题材 番茄小说 收入排行 女频`

3. 用 WebFetch 抓取信息密度最高的2-3个页面，提取：

   * 番茄标签热度数值（万）

   * 短剧改编率（%）

   * 搜索量同比增速（%）

   * 完读率/首章留存率（%）

   * 新人门槛评级

   * 目标题材已有作品及其表现

4. 生成横向对比表，列字段：题材赛道 | 热度 | 增速 | 短剧改编率 | 新人门槛 | 综合赚钱指数

5. 输出 TOP 3 推荐选题，每个附：爆款公式 + 代表作 + 平台适配 + 避坑提示

**输出文件**：`static/market_research.md`

**红线**：

* 必须标注数据来源与时间，网文市场变化快，过期数据会误导

* 热度≠赚钱，必须叠加"改编率+门槛+增速"三维度

* 2026年已降温赛道：纯玄幻仙侠、无脑签到、纯甜宠、老套霸总、狗血宅斗

* 目标题材需确认是否已被过度开发，寻找差异化切入点

### 步骤2.5：核心创意卡录入

**目的**：把作者的核心创意固化为设定基底，后续所有模块以此为约束。

**执行操作**：

### 步骤2.8：素材准备

**目的**：为写作阶段预载行业素材、打脸场景素材、情感线素材，确保专业细节可信。

**执行操作**（行业素材按核心创意卡指定的行业产出）：

3. **打脸场景素材库**（写入 `dynamic/material-prep-report.md`）：

4. **情感线素材库**（写入 `dynamic/material-prep-report.md`）：

### 步骤3：三幕结构大纲

**目的**：产出200-330章的完整三幕结构大纲（首本限制30-50万字）。

**执行操作**：

1. **确定篇幅档位**：首本限制为"中篇"（30-50万字 / 200-330章 / 单章1200-1500字）
2. **划分三幕比例**：22% : 30% : 30% : 18%（一幕:二上:二下:三幕）
3. **逐卷规划**：

   * 每卷10章，标注卷名、情感目标、核心任务

   * 每章一行：章号 | 内容摘要 | 情绪落点 | 章末钩子

   * 标注爽点章（每3章1小爽）和大爆点章（每10章1大爆）
4. **植入伏笔注册表**：标注每个伏笔的种植章号和计划回收章号
5. **绘制副线编织图**：主线、情感线、成长线、悬疑线、反线、群像线的交汇点

**结构框架（示例）**：

```
幕          卷          章数        情感目标    核心任务
─────────────────────────────────────────────────────────
第一幕      第1卷       1-30        爽+燃      重生归来·初次碾压
重生碾压    第2卷       31-60       燃+紧张    系统升级·正面交锋
─────────────────────────────────────────────────────────
第二幕上    第3卷       61-90       爽+燃      降维打击·行业震动
绝地反击    第4卷       91-120      紧张+燃    资本反扑·法律对决
            第5卷上     121-140     燃+感动    证据收网·信任深化
─────────────────────────────────────────────────────────
第二幕下    第5卷下     141-150     燃+释然    反派反水·真相浮现
巅峰对决    第6卷       151-180     释然+感动  至暗时刻→真相揭露
            第7卷       181-210     感动+满足  监管出手·反派崩塌
            第8卷上     211-220     满足       收网
─────────────────────────────────────────────────────────
```

**节奏铁律**：

* 3章一小爽：每3章必须有打脸/反转/小进展

* 10章一大爆：每10章一个重大爆点（见爆点清单）

* 憋屈不超2章：主角受委屈最多2章，第3章必须反击

* 每章末留钩子：章末必须有悬念驱动翻页

* 3:1张弛比：每3章紧张后必须有1章释放/日常/情感

**输出文件**：`static/outline.md`

### 步骤4：人物档案

**目的**：产出完整人物档案，确保角色有灵魂、有区分度、有成长弧光。

**执行操作**：

**加载角色模板库**：读取 `knowledge/character-templates.md`，按6种角色模板（主角/反派/导师/对手/恋爱对象/配角）的元素清单为每个角色填写：

1. **基础设定**：姓名/年龄/外表标签/身份
2. **核心能力**：逆袭资本或威胁来源
3. **致命缺陷**：导致困境或 downfall 的性格弱点
4. **前史创伤**：塑造行为动机的过去事件
5. **人物弧光**：从A状态到B状态的成长/堕落轨迹
6. **语言指纹**：句长偏好、用词偏好、说话节奏、口头禅
7. **反差点**：外表vs内在、公开vs私下的反差
8. **角色语言档案**（从character-templates.md的语言档案模板提取）：

   * 词汇偏好（古语/现代/方言）

   * 句式特征（短句/长句/反问多）

   * 口头禅（每章至少2次）

   * 情绪表达方式（不直接说，通过动作暗示）

   * 禁用词（角色不会说的词）

#### Soul Field 铁律

> **定义**：Soul Field（灵魂场）是角色的不可违背的核心特质集合，用于防止人物漂移。

**每个角色必须定义以下Soul Field元素**：

| 元素    | 说明                | 示例（主角）               |
| ----- | ----------------- | -------------------- |
| 核心信念  | 角色最深层的价值观，不会因剧情改变 | "良知不是软肋，是底线"         |
| 行为边界  | 角色绝对不会做的事         | 绝不会为了利益牺牲无辜者的健康与权益   |
| 情感锚点  | 角色所有情绪的根源         | 至亲的遭遇——一切行为的起点       |
| 语言DNA | 角色说话的不可替代特征       | 短句利落+方言口头禅+固定比喻习惯    |
| 反应模式  | 面对压力时的固定行为模式      | 紧张时沉默不说话，反击时语速变快句子变短 |

**Soul Field 检查规则**：

* 每章写作前加载角色Soul Field，确保本章行为不违背

* 如剧情需要角色"违背"Soul Field，必须铺垫充分的转变动机

* G6门禁检查：本章角色行为是否与Soul Field一致

* 违背Soul Field且无铺垫 → G6失败，触发重写

**输出文件**：`static/characters.md`

### 步骤7：创意扰动审查

**目的**：在大纲和人物定稿前，进行一次全局创意审查，防止同质化。

**执行操作**：

1. **加载反AI模式清单**：读取 `knowledge/anti-ai-patterns.md`，提取4层检测规则（词汇/句式/结构/情节），作为大纲和人物的AI味自查基准

2. **同质化自检**：

   * 与市面已有\[题材]/重生/打脸小说对比，找出雷同点

   * 检查开头方式是否与同类作品趋同

   * 检查金手指设定是否与其他系统流小说撞车

3. **创意扰动注入**：

   * 如果检测到同质化风险，注入1-2个反预期元素

   * 扰动选项示例：

     * "视角偏移"：用配角视角开场再切回主角

     * "物件叙事"：用一个物件串起全章

     * "反预期反应"：角色做出意料之外但合理的反应

   * 扰动是"给选项不替决定"，作者可选一个或全部拒绝

4. **差异化确认**：

   * 明确本作品与同类作品的3个核心差异点

   * 差异点写入创意卡，作为写作约束

**输出文件**：审查结果写入 `dynamic/decisions.md`

### G3：写作门

**目的**：生成本章草稿并进行禁词扫描。

**执行操作**：

1. **写作前准备**：

   * 加载本章大纲条目（内容摘要+情绪落点+章末钩子）

   * 加载本章涉及角色的Soul Field和**角色语言档案**（来自步骤4，含词汇偏好/句式/口头禅/情绪表达/禁用词）

   * 加载G2提取的样本特征卡

   * 加载主角语言指纹库

   * 检查 `rhythm_tracker.json` 确认本章是否为爽点章/爆点章

   * **加载写作Agent prompt**：读取 `prompts/writer-prompt.md`，作为草稿生成的系统prompt，注入以下约束：

     * 写作优先级：冲突 > 好奇心 > 情感 > 进度 > 描写

     * 场景公式：每个场景必须包含目标/冲突/风险/神秘/决策

     * 章节公式：开头→冲突→升级→决策→钩子

     * 冲突引擎：生成多层冲突（外部/内部/社会/资源/时间压力/身份）

     * 好奇心引擎：制造问题但不立刻回答

     * 留存检查清单：冲突/好奇心/进度/情感张力/钩子/结尾期待

   * **加载题材适配参数**：读取 `knowledge/genre-guides.md`，提取当前题材的：

     * 对话占比目标（如古言50-70%/都市40-60%/玄幻30-50%）

     * 爽点密度（如3章1爽/5章1爽）

     * 铺垫容忍度

     * 按场景类型动态调整对话占比（冲突60-80%/日常40-60%/过渡20-40%）

   * **加载钩子系统**：读取 `knowledge/suspense-hooks.md`，选择本章钩子类型（10种），设计章末钩子

2. **Scene-Sequel场景规划**（草稿生成前必做）：

   * 从 `dynamic/templates/scene-plan.md` 加载场景规划模板

   * 为本章每个场景填写Scene-Sequel结构：

     * **Scene层**：Goal（场景目标）→ Conflict（3层递进阻碍）→ Disaster（灾难结尾，禁止"干净成功"）

     * **Sequel层**：Reaction（即时身心反应，实时呈现）→ Dilemma（两难选项，各有代价）→ Decision（决策生成下一场景Goal）

   * 灾难类型必须选其一：flat\_no（直接失败）/ yes\_but（达成但带来新问题）/ no\_and\_furthermore（失败且更糟）

   * 标注爽点模式（越级反杀/打脸权威/反派翻车/甜蜜超预期/无）

   * 将填写完成的场景规划存入 `dynamic/scene-plan.md`（从模板复制到动态轨）

   * **检查清单**：每个场景有Goal、Conflict≥3层、以Disaster结尾、无"yes"场景、Sequel中Reaction实时呈现

3. **草稿生成**：

   * 单章字数目标：1200-1500字（中文字符，不含标点）

   * 前3章特殊要求见"四、前3章特殊流程"

   * 写作时遵循以下约束：

     * 长短句交替（σ²≥8，目标≥10）

     * 段落长短交替（Pσ²≥20，目标≥28）

     * 句式波动明显（BurstCV≥0.40，目标≥0.50）

     * 段落节奏变化（ParaCV≥0.30，目标≥0.40）

     * 短语不重复（3gramUniq≥0.85，目标≥0.90）

     * 用词多样（TTR≥0.40，目标≥0.48）

     * EGR为参考指标，不做硬门禁

     * 植入语言指纹≥2次/章

     * 章末必须留钩子

     * 对话与叙述比例适当（按场景类型动态调整：冲突60-80%/日常40-60%/过渡20-40%）

   * **R1-R5写作铁律**（来自Scene-Sequel引擎，违反则G3失败）：

     * **R1 禁止情绪标签化**：不得直接命名情绪（"他感到愤怒"），必须通过身体反应、动作、环境暗示展示（"指节发白，牙关咬紧"）

     * **R2 强制内心过程≥20%**：本章至少20%篇幅为角色的实时内心过程（感知→判断→决策），非总结性心理旁白

     * **R3 强制句子节奏变化**：每200字内必须出现至少1个短句（≤5字）和1个长句（≥20字），打破匀速节奏

     * **R4 禁止场景结尾总结**：场景不得以总结性句子收尾（"这一天就这样过去了"），必须停在动作或对话的中间状态

     * **R5 对话必须携带潜台词**：每句对话至少有一层未明说的含义，通过上下文、语气、停顿传递，禁止直白信息传递

4. **Humanizer去AI化处理**（草稿生成后自动执行）：

   * 加载 `prompts/humanizer-prompt.md`，按3-Pass管道处理草稿：

     * **Pass 1 Detection**：扫描AI典型模式（词汇/夸张/同义词循环/叙事犹豫/机械排比/泛化描述/对话标签滥用/情感标签/华丽堆砌/系动词回避）

     * **Pass 2 Rewrite**：对标记内容执行改写，保留作者voice和角色对话模式，应用改写原则表

     * **Pass 3 Audit**：最终扫描，确保无遗漏AI-isms

   * 改写结果替换草稿，进入禁词扫描

   * Humanizer Report存入 `dynamic/compliance-log.md` 的反AI检测区域

5. **禁词扫描**：

   * 扫描政治敏感词、色情敏感词、暴力敏感词

   * 扫描番茄平台违禁词表

   * **扫描反AI模式**：按 `knowledge/anti-ai-patterns.md` 4层清单扫描：

     * 词汇层面：不禁/竟然/一股XX涌上心头/嘴角微微上扬等（限用词全章≤1次）

     * 句式层面：随着...也.../他不知道的是/仿佛...一般等

     * 结构层面：战斗三步曲/完美对话/角色同质化等

     * 情节层面：机械降神/无代价胜利/全员崇拜等

     * 命中结果写入 `dynamic/compliance-log.md` 的反AI检测区域

   * 扫描结果写入 `dynamic/compliance-log.md`

**G3通过条件**：

* 场景规划完成（`dynamic/scene-plan.md` 已填写，每个场景有Goal/Conflict/Disaster）

* R1-R5写作铁律全部满足

* Humanizer 3-Pass处理完成（Pass 1检测→Pass 2改写→Pass 3审计）

* 草稿字数在1200-1500字之间（中文字符，不含标点）

* 禁词扫描无命中

* 章末有钩子

**G3失败处理**：

* 场景规划缺失 → 返回步骤2补充Scene-Sequel结构

* R1-R5违反 → 针对具体规则重写违规段落（如R1违反则将情绪标签改为身体反应展示）

* Humanizer检测到AI模式 → 按改写原则表替换，重新审计

* 字数不足 → 补充细节和对话

* 字数超标 → 精简描写，拆分为两章

* 禁词命中 → 替换为安全表述

### G5：metrics指标门

**目的**：用量化指标确保文风达到人写标准，消除AI检测风险。

**设计原则**：硬门禁指标全部为纯统计方法，不依赖词库，不受题材影响。依赖词库的EGR/Cσ²等降级为参考指标，仅预警不拒绝。

**执行操作**：

1. 用 `tools/metrics.py` 计算本章草稿的7项硬门禁指标：

| 指标        | 含义               | 门限    | 人写区间  | AI区间  |
| --------- | ---------------- | ----- | ----- | ----- |
| σ²        | 句长方差（标准差）        | ≥8    | >10   | <5    |
| TTR       | 用词多样性（独特词/总词）    | ≥0.40 | >0.48 | <0.30 |
| Pσ²       | 段长方差（标准差）        | ≥20   | >28   | <12   |
| BurstCV   | 句长变异系数（std/mean） | ≥0.40 | >0.50 | <0.30 |
| ParaCV    | 段长变异系数（std/mean） | ≥0.30 | >0.40 | <0.20 |
| 3gramRep  | 3-gram重复率        | ≤0.08 | <0.06 | >0.10 |
| 3gramUniq | 3-gram唯一率        | ≥0.85 | >0.90 | <0.70 |

1. 用 `tools/metrics.py --aitext` 计算参考指标（仅预警，不做硬门禁），包含AITextDetector第二层AI句占比检测：

| 指标        | 含义                   | 门限     | 说明                              |
| --------- | -------------------- | ------ | ------------------------------- |
| EGR       | 情感颗粒度比               | ≤2.0   | 依赖词库，易误判特定题材                    |
| Cσ²       | 连接词密度方差              | ≥0.15  | 依赖词库                            |
| Iσ²       | 信息密度方差               | ≥1.8   | 卷级参考                            |
| 对话占比      | 对话字符/总字符             | 5%-65% | 异常值预警                           |
| 标点CV      | 标点间距变异系数             | ≥0.30  | 标点节奏参考                          |
| Telling总数 | Show Don't Tell违规数   | ≤5     | 参考anti-ai-patterns.md           |
| Telling密度 | Telling/总句数          | ≤0.15  | 参考指标                            |
| AI模式总数    | 反AI检测命中数             | ≤3     | 来源anti-ai-patterns.md+Humanizer |
| AI模式密度    | AI模式/总句数             | ≤0.05  | 参考指标                            |
| AIText比例  | AITextDetector AI句占比 | ≤30%   | 第二层参考检测，使用--aitext启用            |

1. 检查指标是否达标，生成纠正建议，**AI模式命中详情**列出具体命中的模式类型和文本片段，**AITextDetector报告**列出AI句占比和疑似AI句段

**G5通过条件**：

* 硬门禁7项指标全部达标（σ²≥8, TTR≥0.40, Pσ²≥20, BurstCV≥0.40, ParaCV≥0.30, 3gramRep≤0.08, 3gramUniq≥0.85）

* 参考指标不通过不阻塞，但需在gate-log中记录预警

* 如有指纹库，FP≥2

**G5失败处理**（按质检模式）：

* `QC_SKIP`：跳过本门禁，直接进入G6

* `QC_CHECK`：报告失败指标及纠正建议，暂停等待用户决定

* `QC_FULL`：自动修复1次，仍不通过则暂停，等用户决定是否继续修改：

* σ²<8 → 插入短句（3-5字）打断节奏，或将长句拆为两句

* TTR<0.40 → 替换高频词的30%为同义词，加入个人习惯用语

* Pσ²<20 → 合并或拆分段落，制造长短段交替

* BurstCV<0.40 → 插入极短句（2-4字）和长句交替，增加句式波动

* ParaCV<0.30 → 制造长短段差异（1行段+5行段交替）

* 3gramRep>0.08 → 替换重复短语的表达方式，增加句式变化

* 3gramUniq<0.85 → 增加用词和短语多样性

* FP<2 → 植入口头禅/标志性动作

* 修复后重新计算指标，仅自动重试1次；仍不通过则暂停等用户决策

**命令示例**：

```bash
python tools/metrics.py chapters/ch001.md
python tools/metrics.py chapters/ch001.md --json
python tools/metrics.py chapters/ch001.md --aitext
python tools/metrics.py chapters/ch001.md --fingerprint dynamic/fingerprint.json
python tools/metrics.py chapters/ch001.md --aitext --fingerprint dynamic/fingerprint.json
```

| 地点一致            | 本章场景地点是否在地点索引中登记              | `dynamic/location-index.md`                            |

**G6通过条件**：以上11项全部通过

**G6失败处理**（按质检模式）：

* `QC_SKIP`：跳过本门禁，直接进入G7

* `QC_CHECK`：报告失败项，暂停等待用户决定

* `QC_FULL`：自动修复1次，仍不通过则暂停，等用户决定是否继续修改：

* Soul Field违背且无铺垫 → 重写相关段落

* 伏笔矛盾 → 修正伏笔注册表或重写相关段落

* 时间线矛盾 → 以时间线为准修正本章

* 角色年龄/外貌矛盾 → 修正角色状态表或重写相关段落

* 角色知识矛盾 → 修正角色知识追踪表，角色不该知道的信息不得在言行中表现

* 世界观违反 → 修正本章相关设定

* 副线停滞 → 如果连续3章无副线推进，标注下一章必须推进副线

* 主线停滞 → 连续3章无主线推进，标注下一章必须推进主线

* 地点未登记 → 补充录入地点索引表

## 六、前3章特殊流程

> **原则**：前3章决定留存率，是全书的"生死线"。番茄编辑审稿时间约几分钟，前300字决定生死。

### 4.1 前3章质量要求

| 维度    | 标准             | 反面示例              |
| ----- | -------------- | ----------------- |
| 前300字 | 直接冲突切入，无铺垫描写   | 用环境/体感描写开场铺垫      |
| 第一章   | 重生触发 + 初次打脸/反转 | 只有日常交代，无冲突事件      |
| 第二章   | 打脸升级 + 情感线种子   | 冲突原地打转，不升级        |
| 第三章   | 第一个小爽点释放       | 主角仍被动挨打，无爽点       |
| σ²    | ≥10（人写区间）      | 句式单一（AI区间）        |
| 字数    | 1200-1500字     | 严重超标（如1800-2200字） |

### 4.2 前3章特殊流程

1. **双重G5检查**：前3章的metrics指标需达到人写区间（σ²>10, TTR>0.48, BurstCV>0.50, Pσ²>28, ParaCV>0.40, 3gramUniq>0.90），而非仅达标
2. **开篇钩子审查**：前300字必须包含至少1个冲突元素（背叛/危机/反转/悬念）
3. **读者代入测试**：模拟读者视角，检查"前3章是否让人想继续读"
4. **额外打磨轮次**：前3章允许最多2次重写（普通章1次）
5. **用户强制审核**：前3章完成后必须经过G8用户审核，不可跳过

### 4.3 前3章内容规划（示例）

| 章 | 内容                                                      | 情绪落点       | 章末钩子                   |
| - | ------------------------------------------------------- | ---------- | ---------------------- |
| 1 | 主角重生回到关键节点——成果被对手署名抢夺的瞬间。前世隐忍，这一世当场起身反击。金手指激活：识破对手的数据造假 | 先抑后扬→重生爽感  | 对手脸色一变："你怎么知道这些数据是假的？" |
| 2 | 主角用前世记忆提前布局：抢先发布真相+联系关键证人+锁定核心线索。对手反手甩锅，被主角用证据堵死        | 爽：主动出击碾压被动 | 关键人物注意到主角："这个人，变了"     |
| 3 | 第一个小爽点：主角在内部会议上用专业能力当面拆解对手的"方案"——那是剽窃主角的成果，但对手根本不懂精髓    | 爽：专业碾压打脸   | 男二在旁观察，记下一行字："她不一样"    |

## 七、质量标准

### 5.1 核心指标阈值

**硬门禁指标（纯统计，不依赖词库）**：

| 指标                   | 门限值   | 人写区间  | AI区间  | 说明          |
| -------------------- | ----- | ----- | ----- | ----------- |
| σ²（句长方差）             | ≥8    | >10   | <5    | 衡量句式多样性     |
| TTR（用词多样性）           | ≥0.40 | >0.48 | <0.30 | 衡量词汇丰富度     |
| Pσ²（段落长度方差）          | ≥20   | >28   | <12   | 衡量段落节奏      |
| BurstCV（句长变异系数）      | ≥0.40 | >0.50 | <0.30 | GPTZero核心指标 |
| ParaCV（段长变异系数）       | ≥0.30 | >0.40 | <0.20 | 段落节奏变化度     |
| 3gramRep（3-gram重复率）  | ≤0.08 | <0.06 | >0.10 | 短语复用程度      |
| 3gramUniq（3-gram唯一率） | ≥0.85 | >0.90 | <0.70 | 短语多样性       |

**参考指标（仅预警，不做硬门禁）**：

| 指标           | 门限值    | 说明           |
| ------------ | ------ | ------------ |
| EGR（情感颗粒度比）  | ≤2.0   | 依赖词库，易误判特定题材 |
| Cσ²（连接词密度方差） | ≥0.15  | 依赖词库         |
| Iσ²（信息密度方差）  | ≥1.8   | 卷级参考         |
| 对话占比         | 5%-65% | 异常值预警        |
| 标点CV         | ≥0.30  | 标点节奏参考       |

**其他指标**：

| 指标          | 门限值   | 人写区间  | AI区间 | 说明      |
| ----------- | ----- | ----- | ---- | ------- |
| FP（语言指纹匹配）  | ≥2次/章 | >3    | =0   | 个人习惯用语  |
| SC（文风稳定性系数） | ≥0.75 | >0.85 | <0.6 | 跨章指标稳定性 |

### 5.2 章节字数标准

| 维度   | 标准                              |
| ---- | ------------------------------- |
| 单章字数 | 1200-1500字（中文字符，不含标点和空白）        |
| 统计工具 | `tools/chapter-word-counter.py` |
| 超标处理 | 拆分为多章                           |
| 不足处理 | 补充细节和对话                         |

### 5.3 节奏标准

| 规则     | 标准                   |
| ------ | -------------------- |
| 3章一小爽  | 每3章必须有打脸/反转/小进展      |
| 10章一大爆 | 每10章一个重大爆点           |
| 憋屈不超2章 | 主角受委屈最多连续2章          |
| 章末钩子   | 每章末尾必须留悬念            |
| 3:1张弛比 | 每3章紧张后必须有1章释放        |
| 伏笔回收预警 | 超20章未回收标黄，超40章标红强制处理 |

### 5.4 平台合规标准

| 规则    | 标准                                   |
| ----- | ------------------------------------ |
| AI检测  | σ²/Pσ²/BurstCV/3gramUniq必须在人写区间或达标区间 |
| 意识形态  | 不渲染系统性歧视/负面价值观                       |
| 敏感内容  | 无政治/色情/暴力违禁词                         |
| 正面价值观 | 良知、务实、互助、女性力量                        |

## 八、故障恢复协议

### 6.1 会话断开恢复

**场景**：写作过程中会话意外断开（如超时、网络中断、进程崩溃）。

**恢复流程**：

1. 读取 `dynamic/gate-log.md`，确认断开时最后通过的门禁：

   * G3写作中断 → 读取 `chapters/chXXX_draft.md` 草稿，从断点继续

   * G4/G5/G6质检中断 → 重新执行当前门禁

   * G7落盘中断 → 检查已落盘的文件，补全未完成的WRITE-CHECK

   * 上一章G7已通过 → 正常开始下一章

2. 读取 `dynamic/progress.md` 确认当前章号

3. 读取18个动态轨恢复全部状态

4. 从断开点继续执行，不重复已完成的步骤

**草稿文件**：

* G3写作的草稿即 `chapters/chXXX_draft.md`，终稿为 `chXXX_final.md`

* G7落盘成功后删除临时文件

* 恢复时如发现临时文件存在，说明G3未完成

### 6.2 子Agent调用失败处理

**场景**：门禁检查中调用的工具（如metrics.py、chapter-word-counter.py）执行失败。

**处理策略**：

| 失败类型         | 处理方式                                  |
| ------------ | ------------------------------------- |
| 工具不存在        | 打印警告，使用内置简化逻辑替代，记录到 `gate-log.md`     |
| 工具执行超时       | 重试1次，仍超时则跳过该项检查并标记为"待人工确认"            |
| 工具输出异常       | 记录原始输出到 `dynamic/decisions.md`，请求人类确认 |
| 依赖缺失（如jieba） | 使用降级方案（按字符计算TTR），打印警告                 |

**原则**：工具失败不阻塞创作流程，但必须在 `gate-log.md` 中标记，并在下次会话时优先修复。

### 6.3 门禁连续失败处理

**场景**：某一门禁连续3次未通过。

**处理策略**：

1. 记录失败原因到 `dynamic/gate-log.md`
2. 暂停当前章节的写作循环
3. 向用户报告失败原因和建议修改方向
4. 等待用户指示（重写/跳过/修改大纲/调整参数）
5. 用户确认后从G1重新开始当前章节

## 九、执行原则

### 7.1 核心原则

| 原则         | 说明                                             |
| ---------- | ---------------------------------------------- |
| **一次一章**   | 每次循环只写一章，不批量生成。每章完成后等待用户指示或自动进入下一章             |
| **门禁必过**   | 任何门禁未通过不得进入下一阶段。QC\_FULL模式下自动修复1次，仍不通过则暂停等用户决策 |
| **用户只审G8** | G1-G7全自动执行，用户只需在G8（人类终审）时介入。前3章除外——前3章强制G8审核   |
| **状态落盘优先** | 任何操作完成后立即落盘。宁可多写一次文件，不可丢失状态                    |

### 7.2 写作约束优先级

当约束冲突时，按以下优先级处理：

```
1. 平台合规（违禁词/意识形态）— 一票否决
2. Soul Field一致性 — 不可违背
3. 核心创意卡约束 — 不可偏离
4. 节奏铁律（3章爽/10章爆/憋屈≤2） — 必须满足
5. metrics指标门限 — 必须达标
6. 字数标准（1200-1500） — 必须满足
7. 伏笔回收时效 — 超期强制处理
8. 文风稳定性 — 尽量保持
```

### 7.3 自动化与人工分工

| 环节          | 自动/人工     | 说明             |
| ----------- | --------- | -------------- |
