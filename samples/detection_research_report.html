AI文本检测方案调研报告

调研时间：2026-09-05 | 调研范围：学术论文、开源项目、平台实践、社区共识

核心结论：当前系统的 σ²/TTR/Pσ² 三个指标方向正确，实测能有效区分人写和AI；但 EGR 和 Cσ² 依赖硬编码词库，本质脆弱，应替换为不依赖词库的统计方法。最佳方案是分层架构：纯统计指标（无需模型）+ 轻量ML分类器（可选）+ 结构特征（需开发）。

一、问题诊断：为什么词库方式会误标记

根本缺陷：词库覆盖 vs 写作多样性的矛盾

EGR 的计算逻辑是 笼统情感词数 / 感官词数，靠两个固定词库做匹配。问题在于：

  • 题材差异：《攻玉》是探案文，不写"胃紧""视野发白"；《太傅》是搞笑文，不用"CPU烧了"
  • 补丁陷阱：每发现一个误报就补词，但换题材又误报——永远补不完
  • 经典反例：老舍《林海》被某工具判为99.9% AI，朱自清《荷塘月色》超60%疑似AI——统计指标连经典文学都会误判

这不是阈值调不调的问题，而是方法论本身不适合。词库匹配只能作为弱参考信号，不能做门禁判据。

2.2 平台实际做法（番茄/晋江/起点）

关键发现：三大平台都不只看文本本身，而是结合创作过程做判断。

  • 晋江：要求作者提交 AI 对话前的原稿 + AI对话记录 + 输出稿，还原创作过程，而非单纯给文本打分
  • 番茄：对"情节套路化、叙事逻辑混乱、大篇幅AI生成"做治理，允许AI辅助但要求≥30%人工加工
  • 起点：要求作者主动申报AI使用，核心剧情禁止依赖AI

误判案例：作者"小风熊"将2017年写的小说（AI尚未诞生）丢进检测器，被判"90%疑似AI生成"。

三、六大候选方案技术深挖

方案1：N-gram重复率 推荐·纯统计

原理：统计文本中3-gram/4-gram的重复比例。AI文本倾向复用相同短语结构，人写更多样。

为什么比EGR好：不需要词库，纯统计，不受题材影响。AI的"然而不仅如此与此同时"会自然产生高重复率。

实现：

from collections import Counter

def ngram_repetition(text, n=3):
    chars = list(text.replace(' ', '').replace('\n', ''))
    ngrams = [tuple(chars[i:i+n]) for i in range(len(chars)-n+1)]
    counts = Counter(ngrams)
    total = len(ngrams)
    repeated = sum(1 for c in counts.values() if c > 1)
    return repeated / total if total > 0 else 0

参考阈值（需用我们的样本校准）：

  • 英文参考：AI 3-gram重复率显著高于人写
  • 中文网文：无公开基准，需用3篇人写+1篇AI样本自测
  • 建议测试 n=3 和 n=4 两个值

优势：零依赖、极快、不误判特定题材

局限：短文本不稳定；对经过润色的AI文本可能失效

方案2：突发性 (Burstiness) 推荐·纯统计

原理：GPTZero的核心指标之一。衡量文本在整个文档中的波动程度。

多种实现方式：

实现公式数据来源难度
句长变异系数 (CV)std(句长) / mean(句长)句子已有（σ²的变体）
Goh-Barabási参数B(σ-μ) / (σ+μ)句长分布简单
Fano因子σ² / μ任意粒度简单
Token级突发性std(per_sentence_surprisal) / mean(...)需LM需模型

参考阈值（第三方检测器，需用我们样本校准）：

文本类型Burstiness (CV)
AI生成 (ChatGPT/Claude)0.15-0.30
AI生成 (Gemini)0.15-0.22
人写（典型）0.60-0.85
人写（创意/口语化）0.80-1.00+

与我们现有σ²的关系：σ²是标准差，Burstiness CV是标准差/均值。后者无量纲、可跨章节比较。建议同时保留两者。

方案3：困惑度 (Perplexity) 推荐·需轻量模型

原理：语言模型对文本的"不意外程度"。AI生成的文本对模型来说更"熟悉"，困惑度低；人写更"意外"，困惑度高。

本地实现方案：

  • Qwen2.5-0.5B + CPU：最小的实用中文模型，可用transformers库CPU推理
  • KenLM：快速n-gram语言模型，需先训练，但推理极快
  • 不需要GPU，但CPU推理较慢（单章约10-30秒）

参考阈值：

文本类型Perplexity
AI生成20-60
人写80-200

优势：单一指标中区分力最强，捕捉语言模型层面的统计一致性

局限：需要模型文件（0.5B约1GB）；CPU推理慢；对短文本不稳定

四、推荐方案：分层架构

1
第一层：纯统计指标（零依赖，立即实现）

保留：σ²（句长方差）、TTR（用词多样性）、Pσ²（段落长度方差）

新增：

  • n-gram重复率（3-gram + 4-gram）— 替代EGR的核心指标，不依赖词库
  • Burstiness CV（句长变异系数 = std/mean）— σ²的无量纲版，可跨章节比较
  • 段落长度CV — Pσ²的无量纲版，社区阈值0.4-1.2(人写)/<0.3(AI)
  • 对话占比 — regex匹配引号内文本，阈值5%-65%为正常
  • 标点节奏CV — 标点间距的变异系数

    • 降级为参考（不做硬门禁）：EGR、Cσ²

2
第二层：轻量ML分类器（可选，推荐集成）

集成 lyc8503/AITextDetector：

  • 107MB模型，CPU推理，专门针对中文网文训练
  • 85%准确率，7个LLM二分类器多数投票
  • Apache-2.0开源，可直接集成或参考实现
  • 作为第二道防线，与第一层指标交叉验证

或者：用我们的4个样本+更多数据训练自己的TF-IDF+SVM分类器

3
第三层：困惑度（可选，需模型）

Qwen2.5-0.5B CPU推理：

  • 单一指标中区分力最强
  • 但需要~1GB模型文件，CPU推理10-30秒/章
  • 适合做最终判定，不适合实时检测

或者使用 KenLM 训练n-gram语言模型，推理更快
